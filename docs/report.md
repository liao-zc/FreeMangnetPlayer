# OmniPlayer 重构与全功能点检报告

更新日期：2026-10-31

本轮目标是把磁力播放、IPTV 直播和共用能力分区维护，并按历史需求清单逐项核对。架构图见 [架构说明](architecture.md)，完整需求及逐项状态见 [全量功能点检清单](requirements-checklist.md)。

## 本轮代码改动

- 将通用设置、显示、路径、更新、媒体格式与大小显示整理到 `com.omniplayer.core`。
- 将磁力搜索模型/结果 UI/链接规范化/JavaScript 桥、BT 任务、播放、下载缓存和媒体库归到 `com.omniplayer.magnet`。
- 将直播列表、源设置、直播播放器、频道持久化、M3U 解析和源读取归到 `com.omniplayer.live`，并拆分独立文件。
- 将全局设置界面归到 `com.omniplayer.settings`。
- 更新 Android Manifest 的组件类名。SharedPreferences 名称、数据键、应用 ID 与外部 magnet 入口保持兼容设计。

## 重要已知限制

本次历史磁力首帧测试只证明单个指定种子在当次网络环境可播放：约 0.1% 下载量时出首帧，但首帧等待约 107 秒；有效下载约 175–736 KB/s。它没有达到快速起播目标，也不能证明十条验收 magnet 的 90% 成功率或固定 2 MB/s。元数据成功、文件列表出现、Peer 可达、收到校验分片和画面起播分别是不同验收条件。

## 需求清单状态

目前能通过静态代码和既有 CI/受控素材证据确认的功能，标为“历史证据”或“结构通过”；依赖公网资源、真实设备、源站页面或未经本轮执行的内容均标为“部分”/“未通过”。完整清单覆盖应用入口、通用设置、磁力搜索/解析/下载/播放/管理、IPTV 源/频道/播放/管理、版本更新、品牌与文档，以及速度、格式和公网可用性要求。
